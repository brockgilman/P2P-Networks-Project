# P2P File Sharing Project

A Python implementation of CNT4007 peer-to-peer file sharing project. Peers exchange pieces of a file over TCP using the simplified BitTorrent protocol.

Each peer can download and upload pieces. Preferred neighbors are selected based on download rates, with random selection once a peer has the complete file. Optimistic unchoking gives another interested peer a chance to download. Peers choose missing pieces randomly and stay running until they know every peer has the complete file.

## Running locally

Use Python 3.9 or newer. The program and tests use only the Python standard library. Run these commands from the repository root. If your system uses `python3`, substitute that for `python`.

```sh
python tools/prepare_demo.py --output runs/demo
python tools/run_local.py runs/demo
```

This creates six peers, numbered 1001 through 1006, on localhost ports 6001 through 6006. Peer 1001 starts with a generated 25 MiB file, split into 16,384-byte pieces. The runner starts the peers in configuration order, waits for them to finish, and checks that every copy has the same size and SHA-256 hash as the original.

Results are saved under `runs/demo/`:

- `peer_<id>/demo.dat`: each peer's complete file.
- `log_peer_<id>.log`: connections, neighbor selections, choking, and download events.
- `console_peer_<id>.log`: process output and errors.
- `verification.json`: file hashes, exit codes, and transfer statistics.

Use a fresh output directory for each run. The preparation script refuses to overwrite an existing directory, and the runner refuses to reuse one that already has peer logs. If the ports are busy, pass a different starting port with `--base-port 7001` when preparing the run. The runner defaults to a 180-second timeout; use `--timeout 300` for a longer run.

To use one of the provided datasets, supply the ZIP downloaded from Canvas:

```sh
python tools/prepare_demo.py --output runs/large --dataset large --source path/to/project_config_file_large.zip
python tools/run_local.py runs/large
```

Use `--dataset small` for the small dataset. 

## Configuration and individual peers

Each peer reads `Common.cfg` and `PeerInfo.cfg` from its current working directory.

`Common.cfg` contains the shared settings. The included defaults are:

```text
NumberOfPreferredNeighbors 3
UnchokingInterval 5
OptimisticUnchokingInterval 10
FileName demo.dat
FileSize 26214400
PieceSize 16384
```

The intervals are in seconds. File and piece sizes are in bytes. `FileSize` must match the actual seed file size.

Each row in `PeerInfo.cfg` has a peer ID, hostname or IP address, listening port, and initial file flag:

```text
1001 127.0.0.1 6001 1
1002 127.0.0.1 6002 0
```

A flag of `1` means the peer starts with the complete file. Place that file at `peer_<id>/<FileName>` before starting it. A flag of `0` means the peer starts empty. At least one peer must have the file. The root configuration files are examples; the seed data is generated by the preparation script, not included in Git.

To start peers manually, open a terminal for each peer and run the entry point with its ID:

```sh
python peerProcess.py 1001
```

Run this from the directory containing the configs, or use an absolute path to `peerProcess.py` when working in a prepared run directory. Start every listed peer in the order shown in `PeerInfo.cfg`. Each peer connects to the peers listed before it, regardless of their numerical IDs. The repository also includes `peerProcess` and `peerProcess.cmd` launchers.

For separate machines, copy the code and matching configs to each machine, set reachable hostnames or IP addresses, and allow the configured TCP ports through the firewall. Place seed files on the appropriate machines and start each peer on its configured host. `run_local.py` only supports localhost runs.

Downloads are written to a `.part` file and renamed when complete. Interrupted downloads do not resume; peers marked `0` start empty on each launch.

## Running with Docker

With Docker and Docker Compose installed, run:

```sh
python tools/prepare_containers.py
docker compose up --build
```

This runs six peers in separate containers using Python 3.11. Each container has its own working directory mounted under `runs/containers/<id>/`, where its files and logs are saved. The peers exit after all downloads finish.

To check a downloaded file against the seed, compare the sizes and hashes printed by:

```sh
python tools/hash_file.py runs/containers/1001/peer_1001/demo.dat
python tools/hash_file.py runs/containers/1002/peer_1002/demo.dat
```

Repeat for the other peers. Run `docker compose down` to remove the containers and network after the demo. The saved files remain. For another run, prepare a fresh directory with `--output` and set `P2P_CONTAINER_ROOT` to that directory before starting Compose.

## Code and tests

- `peerProcess.py`: command-line entry point.
- `p2p/peer.py`: connections, piece requests, neighbor selection, and shutdown.
- `p2p/protocol.py`: handshake, message encoding, and validation.
- `p2p/storage.py`: piece storage and file assembly.
- `p2p/config.py`: configuration parsing.
- `p2p/eventlog.py`: timestamped peer logs.
- `tools/`: run preparation, local launch, and hash checking scripts.
- `tests/`: unit tests and TCP integration tests.

Run the test suite from the repository root:

```sh
python -m unittest discover -s tests -v
```

The tests cover configuration, message formats, piece storage, neighbor selection, connection recovery, and transfers between peer processes.
